# 项目维护规则

适用项目：`ear_malecns_manual_project`。本文件来自用户 2026-10-03 的明确要求，与 `AGENTS.md` 一同随代码版本维护。

## 一、每次项目更新同步文档

四份核心文档固定保存于 `docs/`：

1. `work-log.md`：按日期追加需求、实际修改、验证、产物、已知限制与上传决定。保留历史，不覆盖已有日志。
2. `work-summary.md`：维护当前能力、完成情况、已验证结果、限制和下一步，避免历史数据与当前方案混用。
3. `system-architecture.md`：更新受到影响的模块、数据流、接口、单位、时序、存储布局、依赖和扩展点。
4. `user-manual.md`：更新受到影响的启动方式、操作步骤、参数、导入导出、复现方法和故障处理。

每次修改代码、配置、数据链路、运行方式或项目文档时，都追加工作日志；检查其余三份并更新受影响内容，无需为未变化部分制造修改。交付前检查文档描述与实际文件、命令和验证结果一致。必要时同步 README 与其他相关文档。

记录真实证据，不将历史合成夹具结果替换成真实连接组结果；保持真实结构、预测递质、假设动力学、演示机械响应及已验证 FEM 的区别。未运行的验证标为未验证，未完成的步骤不得记为已完成。

## 二、GitHub 代码同步

远端固定为 `git@github.com:shifengdongma/ear_malecns_manual_project.git`，默认开发/上传分支为 `main`。首次上传由用户本轮请求明确授权，无需再次询问。

**后续每次有代码更新时，先完成代码、必要验证、有关文档和可审查的变更说明，再询问用户“是否将本次代码更新上传至 GitHub？”；只有明确同意才能执行本次 push。未答复、拒绝或笼统的历史同意，都不能视为本次上传授权。** 本地编辑、检查、整理和提交可先完成；不得使用定时任务、钩子或后台程序绕过上传询问。

推送前检查 remote、分支、暂存清单、忽略项和敏感信息；推送后比较本地提交与远端分支，并如实记录结果。保留现有远端历史，不擅自 force push，不上传到其他仓库。若后续用户明确指定本次上传，视为本次授权。

## 三、只上传项目源码及必要配套文本

可提交：`src/`、`scripts/`、`tests/`、`configs/`、`docs/`、README、AGENTS、`.codex/project-rules.md`、`.gitignore`、依赖/环境声明和启动脚本。HTML/CSS/JavaScript 源模板、CSV 配置属于代码配套文本，可提交。依赖声明与锁定清单可提交，已下载或已安装的包不可提交。

不得提交：`data/`、`fem/`、`skeletons/`、`outputs/`、`downloads/`、`build/`、`dist/`、虚拟环境、node_modules、缓存、原始模型/网格/SWC、数据二进制、生成可视化/音视频、包压缩文件及安装文件。`.gitignore` 必须持续覆盖新增的非代码目录和文件类型。

不得提交真实 `.env`、token、密码、SSH 私钥、浏览器配置、个人认证与本地 Codex 认证配置。`.env.example` 仅允许占位符。新增需要版本管理的测试夹具或图示时，先确认确为源码配套材料，并用精确路径调整忽略规则，不能大范围取消数据忽略。

## 四、本机运行约束

项目持久数据、模型、下载缓存、临时文件及结果存储于 H 盘本项目；保留现有 Python 环境位置，不因上传仓库迁移或复制环境包。克隆仓库后的数据恢复方式写入用户手册。人耳优先复用 OpenEar/已有 FEM 输出，重点保持果蝇听觉子图及信号传播链路。
